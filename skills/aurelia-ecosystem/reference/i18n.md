# `@aurelia/i18n` — Internationalization

`@aurelia/i18n` wraps [i18next](https://www.i18next.com) for translation plus number, date, and
relative-time formatting. Import from `@aurelia/i18n`.

**`i18next` is a peer dependency — install it** (`npm i i18next`). Add backend plugins (e.g.
`i18next-fetch-backend`) only if you load translations over HTTP.

## Registration

```typescript
import Aurelia from 'aurelia';
import { I18nConfiguration } from '@aurelia/i18n';
import { MyApp } from './my-app';

Aurelia
  .register(
    I18nConfiguration.customize(options => {
      options.initOptions = {
        lng: 'en',
        fallbackLng: 'en',
        resources: {
          en: { translation: { greeting: 'Hello {{name}}', items_one: '{{count}} item', items_other: '{{count}} items' } },
          de: { translation: { greeting: 'Hallo {{name}}', items_one: '{{count}} Element', items_other: '{{count}} Elemente' } },
        },
      };
    })
  )
  .app(MyApp)
  .start();
```

`initOptions` accepts any i18next init option. For HTTP-loaded resources, set
`options.initOptions.plugins = [Fetch]` and a `backend.loadPath`.

## Translating in templates

The `t` custom attribute translates an element. By default it sets `textContent`; target other parts
with bracket prefixes.

```html
<span t="greeting" t-params.bind="{ name: 'Alice' }"></span>  <!-- interpolation -->
<span t="[title]tooltipKey">hover me</span>                   <!-- attribute target -->
<span t="[html]richKey"></span>                               <!-- innerHTML -->
<img t="[alt]logoAltKey" src="logo.png">
<span t.bind="dynamicKey"></span>                             <!-- key from view-model -->
<span t="items" t-params.bind="{ count: itemCount }"></span>  <!-- pluralization -->
```

The `t` value converter does the same inside interpolations:

```html
<p>${ 'greeting' | t : { name: 'Bob' } }</p>
```

Formatting value converters (all update automatically on locale change):

```html
<p>${ price | nf : { style: 'currency', currency: 'EUR' } }</p>   <!-- number -->
<p>${ joinedAt | df : { dateStyle: 'long' } }</p>                 <!-- date -->
<p>${ updatedAt | rt }</p>                                        <!-- relative time, e.g. "5 minutes ago" -->
```

## The `I18N` service

Resolve `I18N` for translation and formatting in TypeScript, and to switch locale.

```typescript
import { resolve } from 'aurelia';
import { I18N } from '@aurelia/i18n';

export class App {
  private i18n = resolve(I18N);
  currentLocale = '';

  binding() {
    this.currentLocale = this.i18n.getLocale();
  }

  async setLocale(locale: string) {
    await this.i18n.setLocale(locale);        // async — always await; refreshes all bindings
    this.currentLocale = locale;
  }

  formatPrice(value: number) {
    return this.i18n.nf(value, { style: 'currency', currency: 'EUR' });
  }
}
```

```html
<select value.bind="currentLocale" change.trigger="setLocale(currentLocale)">
  <option value="en">English</option>
  <option value="de">Deutsch</option>
</select>
```

`I18N` methods: `tr(key, options?)`, `setLocale(locale)` (async), `getLocale()`,
`nf(number, opts?, locale?)`, `df(date, opts?, locale?)`, `rt(date, opts?, locale?)`,
`uf(string, locale?)` (unformat a number), plus `createNumberFormat`/`createDateTimeFormat`/
`createRelativeTimeFormat` for reusable formatters. The underlying instance is on `i18n.i18next`.

## Reacting to locale changes

A locale change publishes on the EventAggregator. Use the `Signals.I18N_EA_CHANNEL` channel. Per
this package's disposal guardrail, dispose the subscription in `dispose` (permanent teardown), not
`unbinding`:

```typescript
import { resolve, IEventAggregator } from 'aurelia';
import { Signals } from '@aurelia/i18n';

export class Header {
  private ea = resolve(IEventAggregator);
  private subscription: { dispose(): void } | null = null;

  binding() {
    this.subscription = this.ea.subscribe(Signals.I18N_EA_CHANNEL, ({ oldLocale, newLocale }) => {
      // react to locale change
    });
  }

  dispose() {
    this.subscription?.dispose();
    this.subscription = null;
  }
}
```

Template bindings using `t`/`nf`/`df`/`rt` refresh on their own — you only need to subscribe for
imperative side effects.

## Gotchas

- Install `i18next` yourself — it is a peer dependency, not bundled.
- `setLocale` is async; always `await` it (templates won't update until it resolves).
- Pass a real `Date` to `rt`/`df`, not a string or number.
- Use `@aurelia/validation-i18n` to localize validation messages (register after
  `I18nConfiguration`).
- Dispose any EA locale subscription in `dispose`, not `unbinding`.
